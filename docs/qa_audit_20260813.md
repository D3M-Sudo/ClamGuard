# QA Audit — Build & Dynamic Testing, Static Analysis, Fix — 2026-08-13

## Metodologia

Ciclo completo in 3 fasi su richiesta del maintainer:

1. **Build & Dynamic Testing**: build reale (meson/ninja, non mock) installata
   ed eseguita sotto Xvfb con clamav/dbus reali, pilotata a click. Verifica
   rapida delle aree già note (scan, dashboard, icone, VirusTotal/Settings)
   + approfondimento su concorrenza, permessi, file grandi, switch
   clamd/clamscan, flusso firme di terze parti.
2. **Static Code Analysis**: suite completa `ruff`, `bandit`, `mypy`,
   `vulture`, `radon` sull'intero codebase.
3. **Cross-referencing & fix**: ogni sintomo osservato in dinamico
   ricondotto alla causa esatta nel codice, corretto in ordine di gravità,
   con proposte esplicite laddove la scelta di design non era univoca.

Il repository ha ricevuto nel frattempo un redesign completo dell'interfaccia
("Bitdefender-style", sidebar) e modifiche a `clamav.py` per l'esecuzione
via `flatpak-spawn` da parte di altri agenti (Jules/Bolt): l'audit è stato
condotto sul codice risultante da quell'integrazione, non su una versione
precedente.

## Nota metodologica sui limiti dell'ambiente di test

Il sandbox usato per la validazione visiva (Xvfb, rendering software senza
GPU) non rasterizza correttamente alcune icone valide e pre-esistenti nel
codice (confermato con test di controllo), un limite del motore di
rendering di questo specifico container — non un bug applicativo. Per
questo motivo, la validazione delle icone si basa su
`Gtk.IconTheme.has_icon()` (verifica indipendente dall'ambiente) più
verifica visiva incrociata dove possibile, non sulla sola ispezione
visiva. Consigliata una rapida verifica finale su un desktop reale dopo
l'installazione del Flatpak.
